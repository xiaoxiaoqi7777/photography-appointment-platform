# 解忧摄影 前端开发计划

> 依据：`docs/开发计划.md`（总纲）、`docs/API接口约定.md`（接口契约）、两份源文档。
> 本文件只管前端任务与验收；后端任务见 `docs/开发计划_后端.md`。
> 状态标记：`[x]` 未开始 / `[x]` 已完成 / `>` 部分完成

---

## Mock 总原则（贯穿全部阶段）

1. 接口以 `docs/API接口约定.md` 第 5 节为准，请求/响应结构严格按契约编写。
2. 后端接口未就绪时使用本地 Mock 数据推进页面开发；**Mock 必须显式标注**（如目录 `src/mock/` 或代码内 `// MOCK:` 注释、页面开发提示条），不得冒充已联调功能。
3. 后端接口就绪后：删除对应 Mock、切换 axios 真实请求、按"成对验收点"联调，联调通过才算完成。
4. 所有请求经统一 axios 实例：自动携带 `Authorization: Bearer <token>`；`code=40100` 或 HTTP 401 清 token 跳登录；403 统一提示无权限。

## 阶段一：前端骨架 `[x]`

交付物：可运行的 Vite 工程，admin 登录（联调后端）进入管理端布局。

任务清单：

- [x] Vite + Vue3 + TS 工程初始化（`backend/`、`frontend/` 平级，位于仓库 `frontend/`）
- [x] 依赖：Element Plus、Vue Router、Pinia、Axios（不引入其他框架）
- [x] `vite.config.ts`：dev 代理 `/api → http://localhost:8080`
- [x] 目录结构：`src/api/`（axios 实例 + 按模块 api）、`src/router/`、`src/stores/`、`src/layouts/`（用户端/管理端两套）、`src/views/`、`src/components/`
- [x] axios 实例：token 注入、401 跳登录、统一错误提示；响应解包 `{code,message,data}`
- [x] 路由守卫：未登录跳登录页；USER 访问管理端路由跳 403/首页；ADMIN 登录进管理端
- [x] 登录页（仅登录，注册本阶段不做）
- [x] 环境变量集中管理（`VITE_API_BASE` 等，`.env.development`）

验收标准：

1. [x] `npm run build`（含 vue-tsc 类型检查）通过
2. [x] 后端阶段二就绪后成对联调：浏览器 admin/admin123456 登录 → 跳管理端布局 → 页面显示当前用户信息（来自 `GET /api/users/me`）
3. [x] 无 token 直接访问受保护路由被拦截；401 自动回登录页

## 阶段二：用户模块页面 `[x]`

依据：API 约定 5.1。依赖后端阶段三。

- [x] 注册页：用户名 3~20、密码 ≥6、昵称/手机号可选；前后端双重校验；40901 提示"用户名已被占用"
- [x] 登录页完善：按角色跳转（USER→用户首页，ADMIN→管理端）；账号禁用/密码错误提示
- [x] 个人信息页：查看资料、改昵称/手机号、改密码（原密码校验，修改成功重新登录或刷新信息）
- [x] 退出登录：清除本地 token（前端行为，无后端接口，API 约定 U-01）

验收：注册→登录→改信息→改密码→重登全闭环；表单校验与错误提示齐全；token 正确持久化与清除。

## 阶段三：主题与套餐页面 `[x]`

依据：API 约定 5.2/5.3。依赖后端阶段四（此前可 Mock）。

用户端：

- [x] 首页/主题列表页：上架主题卡片（封面占位、名称、标签），按 sort 排序；空态引导
- [x] 主题详情页：主题信息 + 该主题上架套餐列表（价格、精修张数、时长、包含内容）
- [x] 套餐详情页：套餐完整信息 + "立即预约"入口

管理端：

- [x] 主题管理页：分页表格、状态筛选、新增/编辑弹窗、上架/下架开关
- [x] 套餐管理页：分页表格、按主题筛选、新增/编辑（价格两位小数校验、精修张数 ≥1、必须选主题）、上下架开关
- [x] 主题/套餐编辑弹窗支持上传本地封面（补充，JPG/JPEG/PNG、≤5MB；也可继续填写图片地址）
- [x] 无删除按钮（仅上下架，API 约定 T-01）

验收：下架主题/套餐在用户端立即不可见；分页筛选正确；越权（USER 进管理页）被路由守卫拦截；表单校验完整。

## 阶段四：订单页面 `[x]`

依据：API 约定 5.4。依赖后端阶段五（状态机为核心，优先联调）。

用户端：

- [x] 预约下单页：选套餐带出主题、日期选择（禁选早于今天）、时间段下拉（上午/下午/全天）、备注 ≤200 字实时校验、提交前确认
- [x] 我的订单页：状态 Tab 筛选、分页（10 条/页）、订单卡片显示状态与关键信息
- [x] 订单详情页：订单信息、状态时间线（action/from/to/remark/createTime）、操作按钮按状态显隐（取消仅 PENDING；确认交付/申请修改仅 UPLOADED，需二次确认）、拒绝原因展示

管理端：

- [x] 订单列表页：分页 + 状态筛选 + 关键字搜索（用户名/主题）
- [x] 订单处理：确认、拒绝（原因必填弹窗）、标记拍摄完成（二次确认）；操作后刷新列表与状态

验收：非法操作按钮不可见且后端 40900 兜底；他人订单无入口；操作反馈（成功/失败）明确；与后端状态机联调通过 8 种状态流转。

## 阶段五：照片页面 `[x]`

依据：API 约定 5.5。依赖后端阶段六。

管理端：

- [x] 上传页：仅 SHOOTING_DONE / MODIFYING 订单可进入；多选上传（≤20、jpg/jpeg/png、单个 ≤10MB 前端预校验）、进度条、成功/失败清单展示

用户端：

- [x] 照片预览页：交付前展示水印图列表（懒加载 + 灯箱大图），页面不出现原图下载入口
- [x] 交付后出现"下载原图"按钮（单张下载，触发后端文件流）
- [x] 空态（未上传照片）

验收：交付前无任何原图线索；上传失败文件有明确原因；大图浏览流畅、懒加载生效；下载文件名中文不乱码。

## 阶段六：反馈与交付页面 + 收尾 `[x]`

依据：API 约定 5.6/5.7。依赖后端阶段七。

- [x] 申请修改：意见输入必填 ≤500 字校验、提交后状态变更为"修改中"

- [x] 历轮反馈展示：按轮次列出内容与时间，与照片批次对应（订单详情页）

- [x] 收尾：全站空态/加载/错误三态检查；README 补前端启动说明（Node 24、npm install、dev/build 命令、环境变量）

验收：

1. [x] `npm run build` 全绿
2. [x] 与后端成对完成 M7：完整闭环（下单→确认→拍摄完成→上传→预览→反馈→重传→交付→下载原图）浏览器全程走通
3. [x] 按总纲权限矩阵核对前端按钮显隐与后端权限一致（前端隐藏仅作体验，权限以后端为准）

## 阶段依赖与协调

```
阶段一(骨架) → 阶段二(用户页) → 阶段三(主题套餐页) → 阶段四(订单页) → 阶段五(照片页) → 阶段六(反馈交付页)
```

- 阶段一依赖后端阶段二联调登录；阶段三起可先 Mock 并行开发，后端对应阶段完成后切换联调。
- 与后端的里程碑对应关系见总纲第 1 节；每阶段结束出完成报告。
