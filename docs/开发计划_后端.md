## 阶段六：照片模块 `[ ]`

依据：API 约定 5.5、2.8、9.5。

- [ ] 批量上传 `POST /api/admin/orders/{id}/photos`：multipart 字段 `files`、≤20 张、jpg/jpeg/png 白名单、单文件 ≤10MB、文件名净化防路径穿越、落盘 `uploads/{订单ID}/`、同步生成水印（后缀 `_wm`，失败记日志允许水印暂空）
- [ ] 轮次：首次 SHOOTING_DONE→UPLOADED 时 round=1；之后每次 MODIFYING→UPLOADED 加 1
- [ ] 上传成功 → 订单状态 UPLOADED + 日志(UPLOAD)；部分失败返回 success/failed 清单（HTTP 200）
- [ ] 照片列表 `GET /api/orders/{id}/photos`：用户交付前仅返回水印 previewUrl；管理员返回原图入口
- [ ] 预览 `GET .../photos/{photoId}/preview`、下载 `GET .../download`：下载仅 DELIVERED 本人；文件流 + Content-Disposition 中文文件名编码
- [ ] `uploads/` 不暴露为静态资源，全部经鉴权接口读取（API 约定 S-02）

验收：

1. [ ] 伪造 `../`、超大、非白名单文件被拒
2. [ ] 未交付用户请求原图 403；交付后下载成功、中文文件名不乱码
3. [ ] 重传后 upload_round 递增；预览在交付前始终是水印图
4. [ ] 非本人订单 403；非法状态上传 40900

## 阶段七：反馈与交付 + 收尾 `[ ]`

依据：API 约定 5.6、5.7。

- [ ] 提交反馈 `POST /api/orders/{id}/feedback`：仅本人、仅 UPLOADED、content 必填 ≤500、round=已有反馈数+1、photo_round=当前照片轮次（后端推导）、状态→MODIFYING + 日志(MODIFY)

- [ ] 确认交付 `POST .../deliver`：仅 UPLOADED 本人、写 deliver_time、状态→DELIVERED + 日志(DELIVER)
- [ ] 收尾：按 AGENTS.md 权限矩阵跑异常场景清单；README 补后端启动说明（数据库、环境变量、执行 SQL 步骤）

验收：

1. [ ] 完整闭环：下单→确认→拍摄完成→上传→预览→反馈→重传→再预览→交付→下载原图
2. [ ] 反馈轮次与照片轮次对应正确；DELIVERED 后不可再反馈（40900）
3. [ ] `mvn -q package` 全绿；与前端完成 M7 成对验收

## 阶段依赖与协调

```
阶段一(数据库) → 阶段二(骨架+登录) → 阶段三(用户) → 阶段四(主题套餐)
                                            ↘ 阶段五(订单) → 阶段六(照片) → 阶段七(反馈交付)
```

- 阶段二完成后即可与前端联调登录（M1/M2 成对验收）。
- 阶段四起，前端可按 API 契约 Mock 并行开发，接口就绪后切换联调。
- 与前端的里程碑对应关系见总纲第 1 节。
